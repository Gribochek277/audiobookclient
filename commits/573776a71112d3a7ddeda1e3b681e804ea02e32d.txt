message:
sync: keep the listing the CLI just fetched
`audiobook sync` listed the library for real and then threw the result
away: the manifest cache kept whatever it had, so the TUI's automatic
startup sync could keep working from a listing up to six hours old and
newly added books stayed invisible even though the CLI had just seen
them (hit while pruning a real library).

The CLI now resolves its listing through `sync_io::resolve_listing(...,
force = true)`, the same path the TUI's manual `s` uses: it lists for
real, stays authoritative (so `--prune` is unaffected) and writes the
fresh entries back into the cache. The existing cache test now also
asserts the forced listing replaces the manifest with a current
timestamp and the same entries.
