M10: background whole-book downloads, non-blocking chapter loads, duration estimates, UI polish
- dl.rs: per-book download queue (worker thread, mpsc events, cancel flag).
  Order starts at the chapter the player waits for, then the rest in
  playback order. Cached files are skipped; unknown durations are probed
  (ffprobe) so book totals appear without playing.
- playback.rs: BookTotal::{Exact, Estimated, Unknown} + book_total_info();
  Controller no longer downloads on the UI thread: start(ch) is instant,
  tick()/go_chapter() check source.is_local() and report
  TickUpdate::ChapterPending when the file is still downloading.
- tui_app.rs: opening a book never blocks; the waited chapter resolves in
  pump() once cached ("downloading chapter 1…" instead of a freeze).
  Book screen: position / total (with ~ estimate) / remaining, download
  line (⬇ 3/26 · chapter 4 — 12.4 MB → ⬇ cached (26/26)), visible
  per-chapter failures. Library: ⬇ cached marks + legend, per-book
  progress bar, position/total, relative last-played. d restarts the queue.
- cache.rs: stale .partial/.partial.<hex>.partial cleanup before download
  (orphans of killed runs); is_local + public source fields for the queue.
- rclone.rs: --contimeout/--timeout idle timeouts on download+write so a
  stalled FTP transfer fails fast instead of hanging for the hour-long
  DOWNLOAD_TIMEOUT.
- 108 tests green (new: queue order/failure/cancel, BookTotal, pending
  chapter, relative time, cached marks, in-flight size).
